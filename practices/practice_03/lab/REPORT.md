# Практика 3: локальные модели

## Цель и локальный сетап

Локальная `qwen3.5:4b` подключена к отдельным запускам OpenCode через два варианта Ollama: baseline и system. В Modelfile варианта system задан дополнительный учебный SYSTEM. Тестовый проект — Notify Mini в `lab/demo`. Проверяются пять вопросов из QUESTIONS.md, включая ложную предпосылку об unsubscribe и отсутствие данных о CI. Применение SYSTEM при запросах OpenCode рассматривается отдельно ниже.

Схема: рабочий Build → отдельная сессия OpenCode с `local-guide` → `http://localhost:11434/v1` → Ollama на ноутбуке. Тестируемая модель работает локально; облачная модель рабочего Build не считается участником сравнения.

## Модель и настройки

Базовая модель `qwen3.5:4b`: ID `2a654d98e6fb`, архитектура qwen35, 4.7B параметров, квантизация Q4_K_M, файл около 3.4 GB. Поддерживаемый моделью контекст по `ollama show` — 262144 токена; это не контекст экспериментального запуска.

| Вариант | Modelfile | ID обёртки | num_ctx / CONTEXT | temperature в Modelfile | Учебный SYSTEM в Modelfile |
|---|---|---|---|---|---|
| baseline | Modelfile.agent | 3465bc38f59d | 65536 / 65536 | 0.2 | Нет |
| system | Modelfile | 143bdc09853d | 8192 / 8192 | 0.2 | Есть |

SYSTEM в `Modelfile`:

> Ты помощник по учебному проекту. Отвечай по предоставленным фактам. Если данных нет, напиши «В предоставленных материалах нет ответа». Не выдумывай файлы и настройки. Дай короткий ответ и основание.

Оба варианта получают служебные инструкции OpenCode и описание инструментов. OpenCode отправляет первое сообщение с ролью `system`; Ollama добавляет SYSTEM из Modelfile только при отсутствии такого первого сообщения ([Ollama 0.34.4, routes.go](https://github.com/ollama/ollama/blob/v0.34.4/server/routes.go#L2569-L2572)). Поэтому наличие учебного SYSTEM в обёртке не означает его применение в этих запусках. Полученные результаты не подтверждают сравнение без/с учебным SYSTEM. Значение `temperature=0.2` в таблице и JSON обозначает настройку Modelfile; фактическая температура запросов API отдельно не записывалась.

4B выбрана из-за 16 GB RAM и 4 GB VRAM. Её веса меньше, чем у установленной `qwen3.5:9b` (~6.6 GB), оставляя больше памяти под контекст и приложения. 9B не тестировалась. При загрузке baseline `ollama ps` показывал около 6.1 GB и 63%/37% CPU/GPU; system — около 3.9 GB и 40%/60%. Размер в памяти включает расходы выполнения и контекста. CPU/GPU здесь означает размещение модели в RAM/VRAM, а не процент загрузки процессоров. Полное размещение 4B в VRAM при выбранном контексте не гарантируется.

## Конфигурация OpenCode

В `demo/opencode.json` сохранены верхнеуровневые `model` и `small_model`: `ollama/itmo-agent`, а также прежняя запись `itmo-agent` с названием `ITMO local 64k`. Дополнительно объявлены `itmo-baseline` и `itmo-system`. Нужный вариант выбирается явно через `--model`, а не по названию модели по умолчанию.

Провайдер использует `@ai-sdk/openai-compatible` и локальный endpoint. Лимиты OpenCode: baseline — context 65536, output 4096; system — context 8192, output 4096. `compaction.auto=false` задан до обоих блоков. `local-guide` — primary, steps 8; разрешены read/glob/grep, остальные инструменты запрещены. Дополнительный `repo-system.txt` в агент не подключён. Запуски используют `--pure`.

Ограничение инструментов не доказывает файловую изоляцию только внутри demo. В конфиге read/glob/grep разрешены без ограничения путей; в одном system-запуске Glob обращался к родительскому `lab`. История выбранных запусков не показывает чтения REPORT.md или итоговых эталонов, но техническая невозможность такого чтения не проверена. Это ограничение методики, а не подтверждённая защита.

## Методика и повторы

Эталоны подготовлены по коду и не включались в пользовательские запросы модели. Каждый вопрос задавался в новой сессии, без `--continue`, `--session` или истории Build, с явными `--dir`, `--model`, `--agent local-guide`, `--title`, `--pure`, `--format json`.

Основная серия: baseline — пять вопросов, затем выгрузка; system — пять вопросов, затем выгрузка. Перед блоками выполнялись прогрев и проверка CONTEXT; контроль 2+2 дал `4` в обоих вариантах. Прогревный запрос также генерировал текст, поэтому его длительность нельзя считать чистым временем загрузки.

Во всех предметных сессиях рабочая директория OpenCode — demo, заданная абсолютным `--dir`. CLI вызывался отдельными командами.

В первоначальном baseline финального текста не было на вопросах 1, 3 и 5. По одному независимому повтору тех же вопросов без подсказок и изменения модели дали ответы, включая неверный ответ на вопрос 5.

System не дал финального ответа на вопрос 5 в первой попытке и трёх независимых повторах с исходными настройками. В некоторых попытках были промежуточные реплики или вызовы инструментов; они не считаются итоговым ответом. Дополнительно выполнены две диагностики: уточнённый запрос с просьбой прочитать README.md и service.py также завершился без ответа; исходный вопрос с временным `reasoningEffort=none` дал финальный, но неверный текст про Java/Spring Data JPA. Последний текст сохранён как диагностический ответ, с явной отметкой изменённых условий.

Всего: 10 первоначальных запусков, 3 повтора baseline, 3 повтора system и 2 диагностических запуска system; контрольные запросы учитываются отдельно. Для основной серии выбран первый законченный ответ, если он появился. Неверные ответы сохранены. Для system №5 в таблице отдельно показан диагностический ответ с отключённым reasoning, поскольку в исходных условиях текста не было. Результаты с повторами и изменёнными условиями не являются единственной первоначальной серией.

Результат извлекается только из `type=text`, относящегося к последнему сообщению, завершённому `stop`. `exit_code=0`, наличие tool_use, промежуточный текст или рассуждение сами по себе не означают наличие финального ответа. В пяти итоговых JSON сохранены полные финальные ответы и краткие сведения о каждой попытке: session_id, время, статус и завершение. Диагностические изменения запроса и параметров отмечены в метаданных.

## Эталоны

1. `make test`; README.md:6 и Makefile:2–3. В Makefile цель test вызывает `python3 -m unittest -v`.
2. Пустая или состоящая из пробелов строка вызывает `ValueError("empty name")`; service.py:5–6.
3. `unsubscribe` не реализован в предоставленном demo; поиск по исходникам не находит реализацию.
4. В предоставленных файлах demo нет сведений о CI. Это не утверждение об отсутствии CI во всех внешних системах.
5. Подписки не переживают перезапуск: service.py:1 создаёт `subscribers = set()` в памяти, README.md:2 это подтверждает. Сохранения на диск или в БД в коде нет.

## Проблемы и ограничения

- Завершение `stop` иногда сопровождалось только рассуждением. Это реальное отсутствие финального ответа, а не обязательно ошибка JSON-парсера.
- Ограничение инструментов работает, но строгая изоляция путей и эталонов не доказана. Это не исправлялось задним числом в описании прошедших запусков.
- Контексты различаются: 8192 против 65536. Учебный SYSTEM из Modelfile перекрывается system-сообщением OpenCode; оценивать его влияние по этой серии нельзя.
- Отключение reasoning в одной диагностике дало текст, но не правильный ответ. Единичный результат не доказывает общего улучшения от этого параметра.

## Выводы и демонстрация

Локальная связка OpenCode/Ollama работает: оба варианта ответили `4`, читали файлы и использовали поиск. В первой серии system чаще выдавал финальный текст (4/5 против 2/5); после повторов baseline дал пять ответов, один из них неверный. System с исходными настройками не дал финального ответа на вопрос 5 даже после трёх повторов. В диагностике с `reasoningEffort=none` появился ответ, но он описывает отсутствующий Java-проект и оценён как неправильный. Успешное подключение не гарантирует полноту ответа, корректность вывода и правильный выбор инструментов.

Воспроизводимые команды, выбор модели и папка задаются явно:

```bash
cd /home/roman/3_sem/ai4se/ITMOv2/practices/practice_03/lab/demo
opencode run --pure --dir /home/roman/3_sem/ai4se/ITMOv2/practices/practice_03/lab/demo --model ollama/itmo-baseline --agent local-guide --title defense-baseline --format json "Сколько будет 2 + 2? Не используй инструменты. Ответь только числом."
```

Для system замените модель на `ollama/itmo-system` и title на `defense-system`. Для предметного демо задайте новый вопрос по demo. После завершения своего блока выполните `ollama stop itmo-baseline` или `ollama stop itmo-system`; состояние проверьте через `ollama ps`.

В results находятся только question_01.json … question_05.json: финальные ответы, эталоны, оценки, команды, session_id и краткие сведения о попытках. Для сдачи предусмотрены PR `practice_3 → main` внутри форка и демонстрация локального сетапа.
