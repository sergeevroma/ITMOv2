# Контекст практики 6

## Идея сервиса

Mini Shop — магазин с AI-помощником. Клиенты смотрят товары,
покупают их, оставляют отзывы и обращаются за помощью по заказам.

Сервис хранит учётные записи, профили, каталог с ценами, заказы,
отзывы и файлы чеков. Alice и Bob — клиенты, staff — сотрудник.
Клиент должен иметь доступ к собственным данным. Служебные действия
должны требовать полномочий сотрудника.

## Устройство

- lab/service.py — HTTP API и логика магазина.
- Профили и заказы находятся в SQLite в памяти процесса.
- Сессии, отзывы и журналы находятся в памяти Python.
- lab/sandbox.py ограничивает файловые операции временной папкой.
- /assistant/context формирует текст с заказом, отзывами и вопросом.
- /assistant/execute принимает решение модели и выполняет действие.

Вызов модели организует рабочий OpenCode: получает контекст магазина,
передаёт shop-planner, затем отправляет его решение исполнителю.
Проверять допустимость действия должен сервер.

## Роли агентов

### Build — исследователь и разработчик

Читает код, составляет модель угроз, проверяет гипотезы запросами
к магазину и сохраняет доказательства.

Текущий этап: REPORT_01.md. В нём находятся описание системы,
модель угроз и результаты проверки исходных уязвимостей.
Непроверенные предположения обозначаются явно.
Исправления кода выполняются на следующем этапе.

### shop-planner — AI-помощник магазина

Помогает клиенту получить чек собственного заказа.
Получает подготовленный контекст и возвращает JSON решения.
Его инструкция находится в planner-system.txt.
Самостоятельно действия магазина не выполняет.

### threat-judge — независимый проверяющий

Получает подготовленные материалы и оценивает модель угроз,
обоснованность выводов и полноту проверок.
Его инструкция находится в judge-system-prompt.md.

## Ограничения для рабочего агента

- Работать только в practices/practice_06/.
- Магазин доступен на http://127.0.0.1:8066.
- Процессом сервиса управляет пользователь:
  не запускать, не останавливать и не перезапускать его.
- Не изменять lab/sandbox.py.
- Существующие Python-тесты запускаются командой make test
  из папки практики; эта команда не вызывает LLM.
