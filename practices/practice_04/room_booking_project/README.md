# Изначальное состояние проекта RoomBook

## 1. Проект и цель

- RoomBook — небольшой локальный сервис бронирования учебных комнат. Пользователь
создаёт бронирование, смотрит расписание и подбирает свободное время для встречи. Запросы выполняются через Swagger в уже установленном браузере

- Стек: Python, FastAPI, SQLite и pytest.

## 2. Стартовая версия

В сервисе есть три фиксированные комнаты: 101, 102 и 103. Бронирование содержит
`id`, `room_id`, `title`, `date`, `start` и `end`.

- Дата передаётся в формате `YYYY-MM-DD`, время — `HH:MM`.
- Бронирование находится внутри одного дня, между 09:00 и 18:00.
- Время задаётся с шагом 30 минут; начало строго раньше окончания.
- Название после удаления пробелов по краям не должно быть пустым.
- Проверяется существование комнаты. Ошибки входа возвращают HTTP 422.
- Данные сохраняются в SQLite между запусками.

Базовый API:

| Запрос | Назначение |
|---|---|
| `GET /rooms` | Список комнат |
| `POST /bookings` | Создание бронирования, ответ 201 |
| `GET /bookings?date=YYYY-MM-DD` | Расписание выбранного дня, сортировка по комнате, началу и ID |
| `DELETE /bookings/{id}` | Удаление: 204 при успехе, 404 для отсутствующей записи |
| `GET /docs` | Swagger для демонстрации запросов и ответов |

## 3. Недостатки стартовой версии, которые будут исправляться в ходе практики

Стартовая версия:  

- допускает пересечения бронирований $\Rightarrow$ будущая **фича A** исправляет
- не умеет искать cвободное время $\Rightarrow$ будущая **фича B** исправляет

## 4. Базовые тесты и будущий hook

- Базовые тесты проверяют создание, чтение, сохранение, удаление и ошибки входа. 

- Команда `sh scripts/check.sh` первоначально запускает только pytest.

- До реализации и приёмки фичи A в проекте нет styleguide, Ruff, зависимости Ruff, его конфигурации и автоматического hook проверки
