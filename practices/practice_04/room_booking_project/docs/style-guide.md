# Style Guide — RoomBook

Этот документ фиксирует минимально необходимый набор правил для проекта RoomBook, основанный на готовом коде и тестах. Каждое правило сопровождается способом проверки и примером.

Правила ориентированы на быстрые проверки (pytest, Ruff) и ручной обзор только там, где это необходимо.

1. Явные ошибки входа и конфликтов — через HTTPException с понятным detail

- Проверка: pytest (поведенческие тесты), review для формулировок detail.
- Требование: все ошибки пользовательского входа и бизнес-конфликты возвращаются через `HTTPException` с корректным `status_code` и JSON-совместимым `detail`. Для конфликтов бронирований — `{ "reason": "overlap", "conflict_id": <id> }`.
- Пример (app/api.py):

```python
raise HTTPException(status_code=409, detail={"reason": "overlap", "conflict_id": conflict_id})
```

2. Полуоткрытые интервалы времени, проверка пересечений в хранилище

- Проверка: pytest (функциональные тесты).
- Требование: интервал — `[start, end)` с шагом 30 минут, границы 09:00–18:00. Проверка пересечений выполняется в уровне данных единым SQL-условием:
  `new_start < existing_end AND existing_start < new_end`.
- Пример (SQL):

```sql
WHERE room_id = ? AND date = ?
  AND ? < end AND start < ?
```

3. Публичные обработчики — короткие, без логики форматирования данных

- Проверка: review.
- Требование: эндпоинты должны делегировать преобразование и проверки в модели (Pydantic) и слой хранилища; логика в обработчиках минимальна: парсинг входа, вызов слоя данных, возврат результата.
- Пример (антипаттерн): сложные фильтры/сортировки/SQL в обработчике. Перенести в `storage.py`.

4. Сортировки и сериализация — консистентные и детерминированные

- Проверка: pytest (сравнение точного JSON), Ruff (упрощения выражений — W, I), review для спорных мест.
- Требование: списки выдаются в детерминированном порядке (`room_id`, `start`, `id`), сериализация времени — в формате `HH:MM`.
- Пример: `ORDER BY room_id, start, id` и `@field_serializer` для времени.

5. Стиль кода Python — Ruff: базовый набор ошибок и форматирование импортов

- Проверка: Ruff.
- Требование: включить базовые правила ruff: E/F (ошибки/логические проблемы), I (imports), W (предупреждения). Исключить излишне шумные правила до принятия стайлгайда второй версии.
- Пример: лишние/неупорядоченные импорты, пробелы, неиспользуемые переменные — фиксируются.

---

Памятка для тестов

- Тесты называют конкретный баг/поведение.
- Ожидания — литеральные, без вычисления ожидаемого значения кодом.
- Тесты используют реальный API: `TestClient`, статус и JSON сравниваются целиком.
