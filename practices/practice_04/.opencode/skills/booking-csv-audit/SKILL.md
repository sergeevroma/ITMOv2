# Инструкция для агента

## Назначение

Skill применяется, когда пользователь просит проверить CSV с заявками RoomBook.
Результат — список проблем, по которому пользователь решает, что исправить.
Успешная проверка не означает, что заявки сохранены или время зарезервировано.
Инструкция демо для пользователя: [references/demo.md](references/demo.md).

## Входные данные

- Обязательный параметр — путь к CSV; без него требуется уточнение перед началом аудита.
- Адрес API по умолчанию — `http://127.0.0.1:8765`; адрес из запроса имеет приоритет.
- CSV: UTF-8, разделитель — запятая, заголовок `room_id,title,date,start,end`.
- Номера записей начинаются с 2: номер 1 соответствует заголовку.
- Каталог отчётов по умолчанию — `room_booking_project/reports/booking-csv-audit`.
- Исходный CSV используется только для чтения.

## Проверка данных

1. Запусти [scripts/audit_csv.py](scripts/audit_csv.py) из `practices/practice_04`; не переписывай аудит вручную.
   `room_booking_project/.venv/bin/python .opencode/skills/booking-csv-audit/scripts/audit_csv.py --csv <путь> --api-url <адрес> --output-dir <каталог>`.
2. Скрипт читает CSV через `csv.DictReader` и проверяет записи через `app.models.BookingInput`.
3. Код завершения: 0 — чисто, 1 — найдены проблемы заявок, 2 — аудит не завершён.
4. Проверь созданные отчёты; код 1 не требует исправления скрипта или автоматического изменения CSV.

Правила приложения: комнаты 101–103, непустое название, дата `YYYY-MM-DD`.
Время — `HH:MM`, между 09:00 и 18:00, минуты 00 или 30; начало раньше конца.
Не исправляй неверные даты и время предположениями и не удаляй проблемные заявки.

## Поиск конфликтов

1. Для каждой даты валидных заявок получи `GET /bookings?date=YYYY-MM-DD`.
2. Задай тайм-аут HTTP-запросов и проверь статус ответа и структуру JSON.
3. Сравни валидные заявки попарно внутри CSV и с полученными бронированиями.
4. Сравнивай только интервалы одной комнаты и одной даты.
5. Используй полуоткрытые интервалы `[start, end)` и условие:

```text
new_start < existing_end AND existing_start < new_end
```

Соседние интервалы не конфликтуют; точные дубли конфликтуют.
Для конфликта внутри CSV отметь обе записи и номера их партнёров.
Для конфликта с расписанием укажи номер записи CSV и ID бронирования.
Найди все конфликты, а не только первый; сортируй записи отчёта по номеру.

## Отчёт и завершение

- Сохрани JSON с полями `status`, `summary`, `invalid_rows`, `conflicts`, `errors`.
- В `summary` укажи число заявок, невалидных заявок и уникальных заявок с конфликтами.
- Отрази те же результаты в Markdown: итог и таблицы ошибок и конфликтов.
- `status`: `clean` при отсутствии проблем, `issues_found` при найденных проблемах.
- При сбое чтения CSV или API используй `failed` и объясни, что не проверено.
- Недоступность API не означает свободное расписание; не выдавай частичный аудит за полный.
- В ответе покажи статус, краткую сводку и пути к обоим отчётам.
- Приводи вывод выполненной обработки; не заявляй о проверке только по чтению файла.

## Границы работы

Используй API только для чтения: не выполняй POST, DELETE или прямую запись в SQLite.
Не меняй приложение, тесты, зависимости и настройки агента ради выполнения аудита.
Не импортируй даже корректные заявки: внесение бронирований — отдельное поручение.
Если пользователь просит исправить CSV, сохрани отдельный файл после явного поручения.
