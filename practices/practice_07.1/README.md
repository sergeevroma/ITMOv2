# Практика 7.1: ассистент для код-ревью в n8n

На занятии вы разворачиваете n8n, разбираете устройство нод и AI Agent, импортируете базовый сценарий ассистента для ревью и дорабатываете его: основной флоу запускается только при открытии PR, а ревью можно вызвать комментарием `/make_ai_review`.

Базовый JSON-сценарий: [gist](https://gist.github.com/abramov-ks/04bcedd21dc1b29487e716482cef0a3d). Токен GitHub создаётся в [настройках](https://github.com/settings/tokens). Подробности по доступу к n8n и VseLLM — в презентации.

## Домашняя работа: вторая модель, дедупликация и точечные комментарии

Продолжайте сценарий, собранный на занятии. Сделанное на занятии засчитывается. Шаги идут от простого к сложному и выполняются по порядку: каждый следующий опирается на предыдущий.

1. **Добавьте команду `/make_other_ai_review`.** Команда запускает ревью с помощью второй модели — любой, отличной от основной — и публикует результат в PR.
2. **Подключите Data Table.** Самостоятельно разберитесь с механизмом Data Table в n8n и встройте его в сценарий: сохраняйте id PR, для которых уже сделано ревью.
3. **Исключите повторные запуски.** При новом комментарии `/make_ai_review` к PR, который уже есть в таблице, ревью не должно запускаться повторно.
4. **Задание «со звёздочкой»: точечные комментарии.** Доработайте сценарий так, чтобы комментарии публиковались не ко всему diff PR, а точечно — к каждому блоку изменённого кода.

## Что подготовить для сдачи

- Экспорт доработанного сценария в JSON.
- Ссылку на тестовый PR с комментариями ассистента.
- Подтверждение каждого выполненного шага: скриншоты вкладки Executions и, для шагов 2–3, содержимое Data Table.

## Что студент показывает ревьюверу

- Как устроен выбор модели для `/make_other_ai_review` и чем отличаются результаты двух моделей.
- Где хранится состояние и как сценарий решает, запускать ревью или нет.
- Что происходит при повторном `/make_ai_review` к тому же PR.
- Для задания «со звёздочкой» — как diff разбивается на блоки и как комментарии привязываются к строкам.

Наличие ноды в сценарии само по себе не подтверждает её работу — приложите подтверждения реальных запусков.

## Оценка, 12 баллов

Каждый критерий бинарный: баллы начисляются целиком, если критерий выполнен и подтверждён реальным запуском, иначе — 0. Критерии проверяются по порядку: баллы за следующий критерий начисляются, только если засчитаны все предыдущие.

| # | Критерий | Баллы |
|---|---|---:|
| 1 | Команда `/make_other_ai_review` запускает ревью второй моделью, результат опубликован в тестовом PR | 2 |
| 2 | Data Table создана, id PR сохраняется в неё после ревью — видно в содержимом таблицы | 2 |
| 3 | Повторный `/make_ai_review` к уже проверенному PR не запускает ревью — видно в Executions | 3 |
| 4 | Комментарии публикуются точечно, к каждому блоку изменённого кода — видно в тестовом PR | 5 |
| | **Итого** | **12** |
