# Практика 7.2: поддержка пользователя с помощью AI-инструментов

На занятии вы разбираете жизненный цикл GitHub Issues и собираете в n8n Workflow 1: webhook на открытие Issue, AI-классификатор с Structured Output Parser, Switch по типам и проставление лейблов через GitHub API. Дополнительно — ветка first-time-contributor по `author_association` и дедупликация через Data Table.

## Домашняя работа: классификация Issues и еженедельная статистика

Продолжайте сценарий, собранный на занятии. Сделанное на занятии засчитывается. Шаги идут от простого к сложному и выполняются по порядку: каждый следующий опирается на предыдущий.

### Часть 1. Базовый Workflow 1

1. **Классифицируйте Issues.** Webhook на событие `issues` с `action == "opened"`, AI-классификатор возвращает `type` (`bug` / `task` / `feature`) и `confidence`, Switch проставляет лейбл для каждого типа.
2. **Добавьте эскалацию.** Если `confidence < 0.8` или тип не определён, Issue уходит в ветку unknown: лейбл `needs-triage`, комментарий не публикуется.
3. **Вынесите классификатор в Sub-workflow.** Отдельный сценарий с Execute Workflow Trigger принимает `title` и `body` и возвращает `type` и `confidence`. Основной сценарий вызывает его через Execute Workflow node, поведение для Issues всех типов не меняется.

### Часть 2. Еженедельная статистика → Gmail

4. **Соберите данные за неделю.** Cron-триггер `0 9 * * MON` и четыре запроса к GitHub API за прошедшую неделю.
5. **Сгруппируйте статистику.** Code node группирует данные по типу и по автору.
6. **Отправьте отчёт.** Gmail node отправляет HTML-письмо с таблицей статистики.

### Задание «со звёздочкой»: diff недели и AI-аннотация

7. **Сохраняйте статистику.** Результаты каждой недели записываются в Data Table.
8. **Посчитайте изменения.** Сценарий вычисляет Δ к прошлой неделе и показывает его в письме.
9. **Добавьте AI-комментарий.** Basic LLM Chain по данным и Δ генерирует аннотацию изменений, она выводится в письме блоком «AI-комментарий недели».

Для проверки еженедельного сценария не обязательно ждать понедельника: запустите его вручную, но cron-триггер должен быть настроен.

## Что подготовить для сдачи

- Экспорт всех сценариев в JSON: Workflow 1, Sub-workflow классификатора, сценарий статистики.
- Ссылку на тестовый репозиторий с Issues всех типов, включая расплывчатый Issue, ушедший в `needs-triage`.
- Скриншоты вкладки Executions для каждого выполненного шага.
- Скриншот полученного письма; для задания «со звёздочкой» — содержимое Data Table минимум за две недели (вторую неделю можно сымитировать тестовой записью).

## Что студент показывает ревьюверу

- Как классификатор возвращает тип и confidence и как Switch выбирает ветку.
- Почему Issue попал в `needs-triage` и почему на него нет комментария.
- Как основной сценарий вызывает Sub-workflow и что передаётся между ними.
- Какие запросы к GitHub API собирают статистику и как Code node её группирует.
- Для задания «со звёздочкой» — откуда берутся данные прошлой недели и на основе чего LLM пишет аннотацию.

Наличие ноды в сценарии само по себе не подтверждает её работу — приложите подтверждения реальных запусков.
