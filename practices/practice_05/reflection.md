# Рефлексия по практике 5

В практике я попробовал два SDD-фреймворка через OpenCode на существующем Pantry Planner: OpenSpec для гибкого подбора рецептов и GitHub Spec Kit для UI на Flask + Jinja2. Спецификации и реализацию фиксировал отдельными коммитами, а изменение OpenSpec завершил обновлением основной спецификации и архивированием.

До реализации пришлось уточнить совместимость старой сортировки с новым score, направление замен и соответствие полей формы параметрам API. Это помогло определить границы фич и сохранить общее ядро подбора для API и UI.

В OpenSpec работа шла по компактному циклу proposal → specs/design/tasks → apply → archive. В Spec Kit было больше документов и отдельных этапов; clarify помог явно определить поведение пустых полей и ошибок формы. При этом в моих сессиях Spec Kit регулярно создавал пустые файлы или заготовки и заполнял их только после прямого дополнительного указания. Приходилось проверять содержимое артефактов вручную.

В результате получились работающие API и UI, спецификации и тесты. Небольшие недочёты остались. Главный вывод: SDD помогает сформулировать требования и сохранить решения, но качество результата всё равно требует проверки документов, кода и тестовых сценариев. Зелёные тесты и наличие файлов сами по себе не доказывают выполнение всех требований.
