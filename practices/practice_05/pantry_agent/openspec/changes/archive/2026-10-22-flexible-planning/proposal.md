# Proposal

## Why

Текущая версия (V0) подбирает рецепты строго по совпадению ингредиентов и сортирует по имени. Пользователям нужна более гибкая выдача: допуск недостающих ингредиентов, фильтрация по диет-тегам, ограничение по стоимости, учёт замещающих ингредиентов, а также прозрачный score и новый порядок сортировки при включении расширений.

## What Changes

- Добавить опциональные параметры к POST /v1/plan: `allow_missing` (int ≥ 0, по умолчанию 0), `diet_tags` (список строк, по умолчанию []), `max_cost` (число ≥ 0, по умолчанию не задано), `use_substitutions` (bool, по умолчанию false).
- Расширить данные рецептов: поля `tags` (список строк) и `cost` (число). При отсутствии — дефолты `[]` и `0.0`. Жёсткая валидация recipes.json.
- Добавить substitutions.json с отображением замен ингредиентов рецепта в допустимые значения pantry. Отсутствующий файл = нет замен.
- Сохранить нормализацию ингредиентов и тегов через `strip().lower()`. Игнорировать дубли ингредиентов при расчётах.
- Допуск рецепта по условиям: `missing_count ≤ allow_missing`, рецепт содержит все запрошенные теги, `cost ≤ max_cost` (если задан).
- Рассчитывать `score = covered/total - 0.5 * missing/total - 0.1 * min(cost,10)/10`. Отдавать `score`, округляя до 3 знаков после запятой.
- Сортировка: при параметрах по умолчанию — как в V0 (по имени). При включении любого расширения — по `score` по убыванию, затем по имени по возрастанию. `limit` применять последним.
- В ответ каждого рецепта добавлять поля: `missing`, `used_substitutions`, `tags`, `cost`, `score` (помимо `name`, `ingredients`).
- 400-ошибки для новых параметров при неверных типах/диапазонах, сохраняя текущие проверки `pantry` и `limit`.

## Capabilities

### New Capabilities
- `pantry-planning`: гибкое планирование рецептов по списку доступных ингредиентов с опциональными ограничениями, подстановками, расчётом score и расширенной сортировкой.

### Modified Capabilities
- (нет)

## Impact

- Код: `src/planner.py` (ядро), `src/app.py` (валидация входа, контракт ответа).
- Данные: обновить `src/data/recipes.json` (добавить `tags`, `cost`), добавить опциональный `src/data/substitutions.json`.
- Тесты: новые unit и API сценарии для параметров V1, перестановок и сортировки; регрессионная совместимость V0 по умолчанию.
