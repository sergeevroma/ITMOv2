# Конституция Pantry Planner Agent

## Core Principles

### I. Стабильность API (контракт V1)
- Контракт `POST /v1/plan` стабилен. Обратная несовместимость MUST NOT вводиться без повышения
  MAJOR и документированного плана миграции.
- Валидация строгая: `pantry` MUST быть непустым списком строк; `limit` MUST быть целым числом
  >= 1 при наличии; некорректный ввод MUST приводить к HTTP 400 с понятным сообщением.
- Поведение по умолчанию сохраняет строгий отбор V0 при отсутствии включённых расширений V1.

Обоснование: стабильные публичные контракты предотвращают поломки клиентов и обеспечивают
предсказуемую интеграцию.

### II. Единый источник истины (планирование и валидация)
- Планирование, нормализация, валидация и расчёт `score` MUST находиться в общем ядре
  (например, `planner.py`). API и UI MUST вызывать это ядро; дублирование логики в роутингах,
  представлениях или шаблонах MUST NOT выполняться.
- UI MUST NOT вычислять или переопределять `score`, сортировку или `limit`. Они вычисляются
  централизованно и передаются в UI.

Обоснование: единая реализация исключает расхождения и снижает риски сопровождения.

### III. Детерминированная нормализация и порядок
- Нормализация ингредиентов: `strip().lower()`; дубликаты игнорируются.
- Строгий режим (V0): рецепт включается только при наличии всех ингредиентов. Результаты
  сортируются по имени рецепта (возрастание). `limit` применяется последним.
- Расширения V1: при использовании любых из `allow_missing`, `diet_tags`, `max_cost`,
  `use_substitutions` результаты упорядочиваются по `score` (убывание), затем по имени
  (возрастание). `limit` применяется последним.
- Формула `score`:
  `score = covered_count/total - 0.5*missing_count/total - 0.1*min(cost, 10)/10`, где `total`
  — количество уникальных нормализованных ингредиентов.

Обоснование: детерминизм обеспечивает воспроизводимость и надёжное тестирование.

### IV. Договоры данных и замены
- `recipes.json` MUST содержать `name` и как минимум один непустой элемент в `ingredients`.
  Отсутствующие `tags` по умолчанию равны `[]`, `cost` — `0.0`.
- `substitutions.json` опционален. Замены MUST применяться только при `use_substitutions=true`,
  быть одношаговыми, односторонними и MUST NOT превосходить прямое совпадение pantry.
- Применённые замены MUST фиксироваться строками вида `"scallion<-green onion"`.
- Ответ API в V1 MUST включать `name`, `ingredients`, `missing` (нормализованные),
  `used_substitutions`, `tags`, `cost` и `score`. Пустой результат: `{ "recipes": [] }`.

Обоснование: чёткие договоры данных и значения по умолчанию устраняют неоднозначности и упрощают
клиентам работу.

### V. Тестирование и контроль качества
- Unit- и API-тесты MUST покрывать планирование, нормализацию, валидацию, сортировку и расчёт
  `score`.
- Команда запуска тестов: `PYTHONPATH=src .venv/bin/python -m pytest -q`.
- Результаты MUST оставаться детерминированными; изменения, влияющие на порядок, `score` или
  валидацию, MUST сопровождаться соответствующими тестами.

Обоснование: тесты фиксируют инварианты и защищают пользовательское поведение.

## Стек и ограничения
- Среда и инструменты: Python 3.10+, Flask, Jinja2, pytest.
- Минимальный UI использует Flask + Jinja2 и делегирует всё планирование и валидацию общему ядру.
- UI MUST NOT вычислять `score`, сортировку или `limit`.

## Рабочий процесс
- Эта конституция определяет поведение API и UI; она имеет приоритет над разрозненными практиками.
- Поправки SHALL сопровождаться обновлением этого документа, согласованием тестов и, при
  необходимости, документированием миграции.
- Все обзоры MUST проверять соблюдение принципов (общее ядро, детерминизм, стабильные контракты).

## Governance
- Версионирование конституции SHALL следовать Semantic Versioning: MAJOR — для несовместимых
  изменений правил, MINOR — для добавления новых принципов или существенных расширений, PATCH —
  для уточнений.
- Проверки соблюдения MUST выполняться в PR, затрагивающих планирование, валидацию или
  пользовательские результаты.
- Процесс разработки SHALL отдавать предпочтение небольшим, проверяемым изменениям, сохраняющим
  детерминизм.
