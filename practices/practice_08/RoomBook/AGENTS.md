# Работа с RoomBook

Все пути относятся к этому каталогу. Отвечай на русском языке.

## Сначала прочитай

- `README.md` — предметная область и правила бронирования.
- `docs/development.md` — установка, запуск, устройство и текущие ограничения.
- `docs/openapi.json` — контракт для клиента и тестовых ответов сервера.
- Перед изменениями проверь `git status` и относящиеся к задаче код и тесты.

## Ответственность файлов

- `src/roombook/catalog.py` — данные о комнатах.
- `src/roombook/rules.py`, `schemas.py` — время, структуры данных и валидация.
- `src/roombook/service.py` — операции бронирования и подбор времени.
- `src/roombook/repository.py` — SQLite и атомарная проверка конфликта при записи.
- `src/roombook/api.py`, `main.py` — HTTP, ошибки, создание приложения.
- `src/front/index.html` — начальная страница; `styles.css` — общая тема и адаптивная раскладка.
- `src/front/vendor/` — локальный Bootstrap и его лицензия; тему меняй в `styles.css`.
- `tests/` — проверки бэкенда с временными SQLite-базами.

## Изменения и проверка

- Работай в пределах корня проекта RoomBook.
- Пользовательские данные из `data/` не используй в тестах и не перезаписывай.
- Правила бронирования проверяет сервер. Клиентская валидация помогает пользователю.
- Комнаты описывай данными каталога. Не создавай для каждой комнаты отдельный класс.
- Проверку конфликта и вставку сохраняй в одной транзакции.
- При изменении API обновляй экспорт: `.venv/bin/python scripts/export_openapi.py`.
- Полная проверка: `sh scripts/check.sh`. Не ослабляй проверки ради успешного результата.
- В результате перечисли изменения, фактически выполненные проверки и ограничения.
- Не выполняй commit, push, операции с ветками и управление пользовательскими сервисами
  без прямого поручения. Обычные тесты с временными данными входят в проверку изменений.

## Фронтенд

Выбран стек HTML/CSS/JavaScript, Bootstrap 5.3 и pytest + Playwright для браузерных тестов.
Начальный экран свёрстан по `design/main.png` и отдаётся FastAPI с `/`.
Это статическая версия: примеры записей находятся в HTML, запросов к API пока нет.
Фронтенд хранится в `src/front/`, общий сценарий и макеты — в `README.md` и `design/`.
Перед подключением интерактивного сценария заполняется `docs/frontend-spec.md`.
Порядок и содержание артефактов описаны в `docs/development.md`.
Используй готовые компоненты Bootstrap; общие цвета, шрифт и отступы задавай централизованно.
Клиентские тестовые ответы должны соответствовать OpenAPI, а демонстрация — реальному API.
