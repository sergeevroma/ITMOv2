Исходные AI-макеты и Mermaid-сценарий находятся в [README проекта](../README.md).
Ниже — актуальный экспорт состояний после подключения API. Он уточняет макеты:
подтверждение операции расположено над колонками, весь список показан без

Первые восемь кадров сняты при тестах с подменой ответов API. Последние два —
с настоящим FastAPI и временной SQLite-базой. Это позволяет воспроизвести
редкие состояния без изменения пользовательских данных.
В сценарии конфликта комната 102 уже занята с 12:00 до 13:00: существующая
бронь видна в расписании. Повторная попытка использует свободное время 13:00–13:30.

## Проверки

Результат финального запуска: **96 тестов прошли**, из них **35 клиентских**.
Ruff, форматирование и проверка актуальности OpenAPI также прошли.

- [Полная проверка: Ruff, форматирование, OpenAPI, бэкенд и клиент](checks.txt).
- [Отдельный запуск всех клиентских тестов и сохранение скриншотов](client-tests.txt).
- [Контрольная поломка: скрыто сообщение о конфликте](mutation-check.txt).

Клиентские тесты проверяют реальные действия и видимые последствия:
поля и карточки, фильтрацию, обязательный ввод, неверный интервал, ошибки API,
повтор после ошибки, состояния загрузки и пустых данных. Во время задержанного
POST двойной клик, Enter и повторный submit оставляют ровно один запрос.
Аналогично проверяется блокировка повторной отмены.

Полный сценарий без подмены API выполняется с клавиатуры: создать → увидеть
карточку → перезагрузить страницу → увидеть сохранённую бронь → отменить →
перезагрузить и убедиться, что она исчезла. Проверены ширины 390, 1440 и 2560 px.

Для проверки качества теста в отдельной временной копии проекта намеренно
скрыто сообщение ошибки формы. Тест конфликта должен упасть на проверке видимого
сообщения. Рабочий исходник при этом не меняется; затем обычный набор проходит.

Команды воспроизведения находятся в [инструкции разработчика](../docs/development.md).
Обычный запуск тестов не перезаписывает эти артефакты.

## Использование AI

AI-помощник использовался для макетов; Codex — для HTML/CSS/JavaScript,
интеграции с FastAPI, клиентских тестов и анализа результатов запусков.
Примеры постановки задач ниже передают содержание запросов, это не стенограмма:

- Макет: «Создай экран RoomBook: форма новой брони слева, расписание справа;
  покажи ввод, загрузку, успех, пустой список, конфликт и ошибку времени».
- Интерфейс: «Используй HTML/CSS/JavaScript и готовые компоненты Bootstrap.
  Общие цвета, типографику и отступы задай в одном CSS. Подключи настоящий API».
- Тесты: «Проверяй видимый результат, ошибки полей и состояния с подменой API;
  задержи сохранение и проверь, что двойной клик и Enter не создают второй запрос».

После проверки макетов пользователь убрал повторяющие логику надписи и запросил
явный фильтр комнаты в расписании. В реализации выбор комнаты в форме отделён
от фильтра; дата берётся в часовом поясе API. Дополнительно учтён сброс внешнего
поля даты при очистке формы, сохранение подтверждения при ошибке обновления
списка и возможность увидеть созданную бронь после работы с другим фильтром.
Тесты дополнены настоящим API, проверкой сохранения после перезагрузки,
сетевыми сбоями и контрольной поломкой вывода ошибки.
