# Интерфейс RoomBook

Основа: сценарий и макеты в [README](../README.md), изображения в `design/`,
контракт запросов и ответов в [OpenAPI](openapi.json).
Фронтенд находится в `src/front/`; используется HTML/CSS/JavaScript и Bootstrap 5.3.

## Просмотр расписания

1. При открытии страницы загрузить `GET /api/rooms` и `GET /api/booking-rules`.
   Комнаты, вместимость, оборудование и варианты времени берутся из ответов API.
2. По умолчанию выбрать сегодняшний день в часовом поясе из правил бронирования.
   Дата в шапке общая для формы и расписания.
3. Получить `GET /api/bookings?date=YYYY-MM-DD`. При выборе комнаты в расписании
   добавить `room_id`; для «Все комнаты» параметр не передавать.
4. Показать карточки с комнатой, временем, организатором и целью встречи.
   Счётчик отражает число записей по выбранному фильтру.
5. Смена даты или фильтра обновляет расписание. Фильтр расписания не меняет
   выбранную комнату в форме; заполненные поля формы сохраняются.
6. При быстром переключении отменять предыдущую загрузку: устаревший ответ
   не должен подменять расписание для нового выбора.

| Состояние | Видимый результат |
|---|---|
| Загрузка комнат и правил | Индикатор загрузки; зависимые от этих данных элементы недоступны |
| Загрузка расписания | Индикатор и «Загружаем расписание…»; старые карточки скрыты |
| Есть записи | Карточки и актуальный счётчик |
| Записей нет | «Пока нет броней», счётчик 0, пояснение для выбранной даты и фильтра |
| Дата очищена | Предложение выбрать дату; запрос расписания не отправляется |
| Ошибка загрузки | Понятное сообщение и кнопка «Повторить»; выбранные дата и фильтр сохраняются |

Состояния загрузки и результата объявляются через `role="status"`, ошибки — через
`role="alert"`. Все поля имеют подписи, действия доступны с клавиатуры, фокус виден.
На узком экране форма и расписание располагаются друг под другом.

## Создание брони

Организатор выбирает комнату, заполняет ФИО, цель и время, отправляет форму.
Все поля обязательны; пробелы по краям текста удаляются. ФИО ограничено 80 символами,
цель — 120. Окончание должно быть позже начала, время выбирается из правил API.
Проверка клиента помогает исправить ввод; сервер повторно проверяет все правила.

Корректная форма отправляет `POST /api/bookings` с полями `room_id` (число),
`organizer`, `title`, `date`, `start`, `end`. До завершения запроса форма и дата
заблокированы, кнопка показывает индикатор и «Бронируем…». Повторный клик,
Enter и повторное событие submit не отправляют второй запрос.

После 201 показывается подтверждение с комнатой, датой и временем. Форма очищается,
дата сохраняется, фильтр переключается на «Все комнаты», расписание перечитывается,
новая бронь выделяется. Это позволяет увидеть её даже после работы с другим фильтром.
Ошибка обновления списка не отменяет уже полученное подтверждение создания.

При ошибке данные формы сохраняются:

- 422: сообщения `error.fields` рядом с полями, `aria-invalid`, фокус на первом поле;
- 409: сообщение о занятом времени, возможность изменить комнату или интервал;
- сеть, 5xx или повреждённый ответ: сообщение о неполученном подтверждении с просьбой
  проверить расписание перед повтором — запрос мог сохраниться на сервере.

При изменении поля его ошибка снимается; следующая отправка заново проверяет форму.

## Отмена

Кнопка в карточке вызывает `DELETE /api/bookings/{id}`. Любой участник может отменить
любую бронь: это общее расписание без идентификации. Отдельного диалога нет.
Во время запроса кнопка этой брони заблокирована и показывает «Отменяем…».
После 204 показывается подтверждение и перечитывается расписание.
При 404 показывается сообщение об уже отменённой брони и обновляется список.
При другой ошибке карточка сохраняется, кнопка снова доступна для повтора.

## Проверки и результат

pytest + Playwright проверяет видимое поведение с подменой ответов API реального
формата: списки, задержки, успех, 422, 409, 404, 5xx, сетевые ошибки и неверный JSON.
Есть проверки обязательных полей, пробелов вместо текста, неверного интервала,
сохранения ввода, повторной отправки, фильтров, адаптивности и клавиатуры.
Полный сценарий с настоящим API создаёт бронь, проверяет её после перезагрузки,
отменяет и снова проверяет список. Все данные и сервер теста временные.

[Скриншоты реализации и вывод проверок](../evidence/README.md) также фиксируют
уточнения исходных макетов: все записи показываются без пагинации, подтверждение
операции находится над колонками, используются штатные HTML date/select.
